# MVP Scope

## Scope principle

The MVP should validate the connected workflow:

**Wedding setup → planning → guest management → RSVP → vendor discovery → enquiry → quote → selection**

Anything that does not strengthen this loop should be deferred.

## P0 — Required for MVP

### Account and wedding

- Couple sign-up / sign-in
- Create wedding
- Edit wedding details
- Invite collaborator

### Couple dashboard

- Wedding countdown
- Checklist progress
- Guest / RSVP summary
- Vendor progress
- Budget summary

### Events

- Create, edit, delete event
- Assign venue information
- Control which guests are invited

### Guests

- Manual guest creation
- CSV import
- Household / invitation group
- +1 support
- Tags
- Event assignments
- RSVP states
- Dietary / allergy field

### Wedding website

- Theme selection from a very small set
- Couple names
- Wedding date
- Cover image
- Event details
- RSVP CTA
- FAQ
- Publish / unpublish

### RSVP

- Invitation lookup or token link
- Attendance per event
- Dietary requirements
- Confirmation screen
- Couple-side RSVP status

### Planning

- Default checklist
- Add custom task
- Mark complete
- Due date

### Budget

- Total budget
- Category estimates
- Committed amount
- Paid amount
- Remaining budget

### Vendor marketplace

Launch with five categories, for example:

1. Venue
2. Photography
3. Videography
4. Bridal / attire
5. Florist / styling

Required marketplace capabilities:

- Browse category
- Vendor profile
- Search / simple filters
- Shortlist
- Enquire

### Vendor workspace

- Vendor account
- Business profile
- Packages
- Portfolio
- Enquiry inbox
- Lead status
- Quote creation

### Quote and selection

- Couple can view quote
- Couple can compare quote amount and package basics
- Couple can mark shortlisted
- Couple can select vendor
- Selection updates budget commitment

## P1 — Immediately after MVP

- Drag-and-drop seating plan
- Reminder emails
- Custom RSVP questions
- Vendor reviews
- Vendor availability calendar
- File attachments in enquiries
- Simple invoice / payment milestones
- Better wedding website themes
- Guest travel / accommodation fields
- Vendor-specific wedding information sharing
- Collaborator permission levels

## P2 — Expansion

- Contracts and e-signature
- Vendor deposits and payments
- Automated payment reminders
- WhatsApp / SMS messaging
- Seating suggestions
- Venue floor plans
- Registry / gifting
- Photo gallery and guest uploads
- AI planning assistant
- Vendor recommendation engine
- Vendor availability sync with Google Calendar
- Planner agency workspace
- Multi-wedding vendor CRM

## Explicit MVP exclusions

The following should not block the MVP:

- Native Android / iOS application
- Complex accounting
- Multi-currency settlement
- Escrow
- Dispute handling
- Real-time chat
- Marketplace commissions
- Promo codes
- Deep vendor analytics
- Guest social feed

## MVP design constraints

- Couple UI should feel calm and editorial, not like enterprise project management software.
- Guest flows should require as few screens as possible.
- Vendor flows may be more operational but should remain lightweight.
- One source of truth should exist for wedding date, events, guest attendance, and vendor selections.
